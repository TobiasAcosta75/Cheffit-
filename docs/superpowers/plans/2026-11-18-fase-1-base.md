# Chef Deportivo — Fase 1 (Base) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** App web (local) donde el usuario inicia sesión, completa el onboarding (perfil, objetivo, semana de entreno, etapa automática o manual), ve los macros objetivo del día según etapa/peso/tipo de día y registra a mano lo que come con barras de progreso.

**Architecture:** Next.js (App Router, TypeScript) con Server Actions; Supabase local (Docker) para Postgres + Auth + RLS. Toda la lógica nutricional vive en funciones puras en `src/domain/` probadas con Vitest; la UI y las acciones solo orquestan. Multiusuario desde el día 1 vía RLS.

**Tech Stack:** Node 22, Next.js (última estable al ejecutar, `create-next-app`), TypeScript, Tailwind, `@supabase/supabase-js` + `@supabase/ssr`, Supabase CLI vía `npx supabase`, Zod, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-18-chef-deportivo-design.md` (secciones 6.1, 6.2, 6.5, 6.8 (registro manual), 6.13, 6.14, 7 y fase 1 de la sección 8).

**Fuera de esta fase:** chef/recetas (fase 2), IA y peso con propuesta de recálculo y avisos de seguridad (fase 3), plan/meal prep/compras/inventario (fase 4), PWA/deploy en Vercel (fase 5).

## Global Constraints

- Idioma de la UI: español rioplatense ("vos"). Identificadores de código en inglés.
- Zona horaria por defecto del usuario: `America/Argentina/Buenos_Aires`; "hoy" siempre se calcula en la zona del usuario, nunca en UTC.
- kcal = 4·P + 4·C + 9·G, calculadas desde gramos ya redondeados.
- Macros por 100 g en la base de alimentos: kcal, proteínas, carbohidratos, grasas, fibra; cada alimento guarda `source` (`usda`, `argenfoods`, `off`, `manual`, `user`).
- Regla de etapa = g/kg: proteína, carbos día de entreno, carbos día de descanso, grasas. Macros del día = regla × `reference_weight_kg`.
- Alimentos globales (`owner_id` null) solo los edita un admin; un usuario que corrige un global crea una copia propia (`overrides_food_id`) que reemplaza al global solo para él.
- Nunca exponer `SUPABASE_SERVICE_ROLE_KEY` en el navegador (solo scripts y tests).
- Estilo visual: lo elige el usuario en la Tarea 8 antes de construir pantallas.

## Review Focus

1. Registro de noche en Argentina (ej. 22:30 hora local = 01:30 UTC del día siguiente) → debe caer en la fecha local. Test en Tarea 1.
2. Búsqueda sin tildes ni mayúsculas ("limon" encuentra "Limón") → Test en Tarea 4.
3. Usuario que corrigió un alimento global ve solo su copia; otro usuario sigue viendo el global → Tests en Tareas 4 y 5.
4. Editar un alimento después de registrarlo no cambia los macros de registros pasados (snapshot) → Test en Tarea 3.
5. Cálculo automático con gasto bajo (persona pesada y sedentaria) no debe dar carbos negativos ni absurdos → piso de 1,0 g/kg; test en Tarea 2.

### Task 2: Gasto energético, reglas automáticas y etapa activa

**Files:**
- Create: `src/domain/energy.ts`, `src/domain/stages.ts`, ampliar `src/domain/types.ts`
- Test: `tests/domain/energy.test.ts`, `tests/domain/stages.test.ts`

**Interfaces:**
- Consumes: `ISODate` (Tarea 1)
- Produces (en `types.ts`):
  - `type Sex = 'male' | 'female'`
  - `type ActivityLevel = 'sedentary' | 'light' | 'moderate' | 'high' | 'very_high'`
  - `type Goal = 'cut' | 'maintain' | 'bulk'`
  - `interface StageRules { proteinGPerKg: number; carbsTrainingGPerKg: number; carbsRestGPerKg: number; fatGPerKg: number }`
  - `interface Stage extends StageRules { id: string; name: string; startDate: ISODate; endDate: ISODate | null; goal: Goal; mode: 'auto' | 'manual'; notes: string | null }`
- Produces (funciones):
  - `bmrMifflin(sex: Sex, weightKg: number, heightCm: number, ageYears: number): number` — hombre `10w + 6.25h − 5a + 5`, mujer `… − 161`
  - `tdee(bmr: number, activity: ActivityLevel): number` — factores 1.2 / 1.375 / 1.55 / 1.725 / 1.9
  - `autoStageRules(input: { sex: Sex; weightKg: number; heightCm: number; ageYears: number; activity: ActivityLevel; goal: Goal }): StageRules`
  - `activeStage(stages: Stage[], date: ISODate): Stage | null`

`autoStageRules` (valores del spec 6.2; donde el spec da rango se toma el valor que coincide con la imagen "Etapa 3"):
```
cut:      P 2.2, G 1.0, kcalObjetivo = tdee × 0.80
maintain: P 1.8, G 1.0, kcalObjetivo = tdee
bulk:     P 1.8, G 1.0, kcalObjetivo = tdee × 1.10
carbsBase (g/kg) = max(1.0, (kcalObjetivo − 4·P·w − 9·G·w) / 4 / w)     // piso 1,0 g/kg
carbsTraining = round1(carbsBase × 1.10); carbsRest = round1(carbsBase × 0.90)
```
`activeStage`: entre las etapas con `startDate ≤ date` y (`endDate` null o `≥ date`), la de `startDate` más reciente.
